## はじめに

Redis（レディス）は、データをメモリ上に高速に出し入れできる「インメモリ型データストア」です。キャッシュ（よく使うデータの一時保管）やセッション管理などでよく使われます。

この記事では、Redisを運用していると頻繁に使う「**再起動**」と「**保存データの全削除**」のやり方を、初めて触る人にもわかるようにまとめます。あわせて、覚えておくと便利なコマンドも紹介します。

:::message
この記事は Amazon Linux 系の環境で `redis6` というサービス名でインストールされている場合を想定しています。環境によってはサービス名が `redis` や `redis-server` の場合があります。お使いの環境に合わせて読み替えてください。
:::

## 1. Redisを再起動する

設定ファイルを変更したあとや、動作が不安定になったときは、Redisを再起動します。

```bash
sudo systemctl restart redis6
```

- `systemctl` … Linuxでサービス（常駐プログラム）を操作するためのコマンドです。
- `restart` … 一度止めてから、もう一度起動し直すという意味です。
- `redis6` … 操作対象のサービス名です。

### 再起動後の状態を確認する

再起動がうまくいったかどうかは、次のコマンドで確認できます。

```bash
sudo systemctl status redis6
```

`active (running)` と緑色で表示されていれば、正常に動いています。

:::message alert
再起動すると、Redisがメモリ上に持っているデータは消える可能性があります（永続化の設定によります）。キャッシュ用途なら問題ないことが多いですが、本番環境では事前に影響範囲を確認してください。
:::

## 2. Redisの保存データをすべて削除する

「キャッシュをまっさらにしてやり直したい」というときは、保存されているデータを全部消すことができます。手順は次の通りです。

### 手順

```bash
# ① Redisの操作画面（CLI）に入る
redis6-cli

# ② すべてのデータを削除する
FLUSHALL

# ③ 操作画面を終了して通常のターミナルに戻る
exit
```

各コマンドの意味は以下の通りです。

| コマンド | 意味 |
| --- | --- |
| `redis6-cli` | Redisを直接操作するための画面（CLI）に入ります |
| `FLUSHALL` | Redisに保存されている **すべてのデータ** を削除します |
| `exit` | 操作画面を終了して、通常のターミナルに戻ります |

`redis6-cli` を実行すると、プロンプト（入力待ちの表示）が次のように変わります。この状態が「Redisの操作画面に入っている」状態です。

```
127.0.0.1:6379>
```

ここで `FLUSHALL` と入力すると、`OK` と返ってきて削除完了です。

:::message alert
**`FLUSHALL` は元に戻せません。** すべてのデータベース（後述）に入っているデータが、確認なしで一括削除されます。本番環境で実行する前は、本当に消してよいか必ず確認してください。
:::

## 3. 覚えておくと便利なコマンド（Tips）

ここからは、日常の運用で役立つコマンドを紹介します。すべて `redis6-cli` で操作画面に入ってから実行します。

### Redisが生きているか確認する（PING）

Redisがちゃんと応答するかを確認したいときに使います。

```
PING
```

`PONG` と返ってくれば、正常に動いています。

### 1つのデータベースだけ削除する（FLUSHDB）

Redisは内部に複数の「データベース（DB）」を持っていて、番号で区切られています（標準では 0 番〜15 番）。

`FLUSHALL` が **全DBを削除** するのに対し、`FLUSHDB` は **今いるDBだけ** を削除します。「特定の用途のキャッシュだけ消したい」というときは、こちらの方が安全です。

```
SELECT 0     # 0番のDBに切り替える
FLUSHDB      # 今いるDB（0番）だけを削除する
```

### 保存されているキーの一覧を見る（KEYS）

どんなデータが入っているかを確認できます。

```
KEYS *
```

:::message alert
`KEYS *` はデータ量が多いと処理に時間がかかり、その間Redis全体の動作が止まる場合があります。本番環境では避け、代わりに `SCAN` を使うことが推奨されています。
:::

### データの件数を確認する（DBSIZE）

今いるDBに、いくつデータが保存されているかを数えます。

```
DBSIZE
```

### メモリの使用状況を確認する（INFO memory）

Redisがどれくらいメモリを使っているかを確認できます。メモリ不足のトラブル調査で役立ちます。

```
INFO memory
```

表示の中の `used_memory_human` が、人間にわかりやすい単位（MB / GBなど）でのメモリ使用量です。

### 特定のキーだけ削除する（DEL）

全削除ではなく、特定のデータだけをピンポイントで消したいときに使います。

```
DEL キー名
```

## 4. 1行で実行する小ワザ

操作画面に入らず、ターミナルから直接コマンドを渡すこともできます。スクリプトに組み込みたいときなどに便利です。

```bash
# 全データ削除を1行で実行
redis6-cli FLUSHALL

# 応答確認を1行で実行
redis6-cli PING
```

## まとめ

| やりたいこと | コマンド |
| --- | --- |
| Redisを再起動する | `sudo systemctl restart redis6` |
| 状態を確認する | `sudo systemctl status redis6` |
| 全データを削除する | `FLUSHALL` |
| 今のDBだけ削除する | `FLUSHDB` |
| 動作確認する | `PING` |
| キー一覧を見る | `KEYS *`（本番は `SCAN` 推奨） |
| メモリ使用量を見る | `INFO memory` |

`FLUSHALL` をはじめとする削除系コマンドは元に戻せないため、特に本番環境では実行前の確認を習慣にすると安全です。
