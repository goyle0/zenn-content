## はじめに

Git を使っていると「あ、間違えた」「1つ前に戻したい」という場面がよくあります。
そのたびにコマンドを調べ直すのは手間なので、**取り消し・やり直し系を中心に、日常業務でよく使うコマンド**を逆引きでまとめました。

「やりたいこと」から探せる構成にしています。

:::message
このチートシートの前提
- ある程度 Git を触ったことがある人向けに、説明は簡潔にしています。
- `git` は省略せずに書いています（エイリアス前提にしていません）。
:::

## コミットのやり直し・取り消し

| やりたいこと | コマンド |
| --- | --- |
| 直前のコミットを取り消す（変更内容は残す） | `git reset --soft HEAD~1` |
| 直前のコミットを取り消す（ステージも解除、変更は残す） | `git reset --mixed HEAD~1` |
| 直前のコミットを取り消す（変更ごと完全に消す） | `git reset --hard HEAD~1` |
| 直前のコミットメッセージだけ修正する | `git commit --amend` |
| 直前のコミットに、入れ忘れたファイルを追加する | `git add ファイル名` → `git commit --amend --no-edit` |
| 公開済みコミットを打ち消す新しいコミットを作る | `git revert コミットID` |

### `reset` の3つの違い（重要）

`reset` は後ろのオプションで「どこまで戻すか」が変わります。

| オプション | コミット | ステージ | 作業ファイル |
| --- | :---: | :---: | :---: |
| `--soft` | 戻す | 残す | 残す |
| `--mixed`（既定） | 戻す | 戻す | 残す |
| `--hard` | 戻す | 戻す | **消す** |

- **コミットだけやり直したい** → `--soft`
- **ステージングもやり直したい** → `--mixed`
- **全部なかったことにしたい** → `--hard`（作業内容が消えるので注意）

:::message alert
`--hard` は作業中の変更を**完全に削除**します。実行前に本当に消して良いか確認してください。
:::

### `reset` と `revert` の使い分け

- **まだ誰にも共有していないコミット** → `reset` で消してOK
- **すでに push して共有済みのコミット** → `revert`（打ち消しコミットを追加する）を使う

共有済みのものを `reset` すると、他の人の履歴とズレてトラブルの元になります。

## マージ・リベースの取り消し

| やりたいこと | コマンド |
| --- | --- |
| コミットしていないマージを取り消す | `git merge --abort` |
| 完了済みのマージを取り消す（直前の状態に戻す） | `git reset --hard ORIG_HEAD` |
| 実行中のリベースを中止する | `git rebase --abort` |
| 実行中の cherry-pick を中止する | `git cherry-pick --abort` |

:::message
`ORIG_HEAD` は「マージやリベースをする直前の位置」を Git が自動で覚えてくれている目印です。
「マージしたけどやっぱり戻したい」ときの合言葉です。
:::

---

## 作業中の変更を取り消す

| やりたいこと | コマンド |
| --- | --- |
| ファイルの変更を取り消す（最後のコミット状態に戻す） | `git restore ファイル名` |
| すべての変更を取り消す | `git restore .` |
| ステージング（add）を取り消す | `git restore --staged ファイル名` |
| 追跡していない新規ファイルを削除する | `git clean -f` |
| 削除される新規ファイルを事前に確認する | `git clean -n` |

:::message
`git restore` は比較的新しいコマンドです。古い環境では次の書き方になります。
- 変更を取り消す → `git checkout -- ファイル名`
- add を取り消す → `git reset HEAD ファイル名`
:::

:::message alert
`git clean` は追跡外のファイルを削除します。消える前に必ず `-n`（確認だけ）で対象を確かめてください。
:::

## ブランチ操作

| やりたいこと | コマンド |
| --- | --- |
| ブランチ一覧を見る | `git branch` |
| ブランチを作って移動する | `git switch -c ブランチ名` |
| ブランチを移動する | `git switch ブランチ名` |
| ブランチ名を変更する（今いるブランチ） | `git branch -m 新しい名前` |
| ブランチを削除する（マージ済みのみ） | `git branch -d ブランチ名` |
| ブランチを強制削除する | `git branch -D ブランチ名` |
| 削除したブランチを復活させる | `git switch -c ブランチ名 コミットID` |

:::message
`switch` / `restore` は、従来 `checkout` が兼ねていた役割を分けた新しいコマンドです。
`checkout` でも同じことはできますが、意図が分かりやすい `switch` / `restore` が推奨されています。
:::

## 変更を一時退避する（stash）

作業途中で別のブランチに切り替えたいときに便利です。

| やりたいこと | コマンド |
| --- | --- |
| 変更を一時退避する | `git stash` |
| 退避した一覧を見る | `git stash list` |
| 最新の退避を戻す（退避は消える） | `git stash pop` |
| 最新の退避を戻す（退避は残す） | `git stash apply` |
| 退避を捨てる | `git stash drop` |

## 並行作業に便利（worktree）

1つのリポジトリで、複数のブランチを別フォルダとして同時に開けます。
「ブランチを切り替えずに、別ブランチの作業も並行したい」ときに有効です。

| やりたいこと | コマンド |
| --- | --- |
| 別ブランチを別フォルダで開く | `git worktree add ../フォルダ名 ブランチ名` |
| worktree の一覧を見る | `git worktree list` |
| 使い終わった worktree を片付ける | `git worktree remove ../フォルダ名` |

## リモート関連

| やりたいこと | コマンド |
| --- | --- |
| リモートの最新を取り込む（マージまで） | `git pull` |
| リモートの情報だけ取得する（作業には反映しない） | `git fetch` |
| ローカルの変更をリモートに反映する | `git push` |
| ローカルの状態を強制的にリモートへ反映する（安全版） | `git push --force-with-lease` |

:::message alert
`git push --force` は他の人の変更を上書きしてしまう危険があります。
どうしても強制 push が必要なときは、他人の変更を巻き込まない `--force-with-lease` を使ってください。
:::

## 困ったときの駆け込み寺（reflog）

`reset --hard` などで「消したはずの状態」も、しばらくは Git が履歴を覚えています。
**「やらかした！」と思ったら、まずこれを実行**してください。

```bash
# HEAD が動いた履歴を一覧表示（過去の状態がIDで見える）
git reflog

# 戻りたい状態のIDを指定して復元
git reset --hard 戻りたいコミットID
```

:::message
`git reflog` は、直近の操作履歴（どこにHEADがあったか）を記録しています。
`reset --hard` で消したコミットも、ここから復活できることが多いです。
:::

---

## 覚えておくと安心な考え方

- **戻す前に、まず状態を見る** → `git status` / `git log --oneline`
- **共有済み（push済み）は `reset` しない** → `revert` を使う
- **`--hard` と `clean` と `--force` は要注意** → 消える・上書きされる系
- **やらかしても慌てない** → だいたい `git reflog` で戻せる

このチートシートをブックマークしておいて、迷ったときの逆引きとして使ってもらえれば幸いです。
