## この章の要点（忙しい人向け）

- 「**端末同士は通信させない**」が二次感染を止める一番の近道。「閉域網だから安全」は成り立たない
- 2026年は「推奨」の多くが「義務」に。**台帳・連絡体制図・BCP・運用管理規程**は立入検査で現物確認される
- 二要素認証は**2027年4月1日**が期限。パスワードの定期変更要件は削除され、「長く・使い回さない」へ
- IoT・医療機器は「専用SSID＋専用VLAN＋通信先の限定」で隔離する

## 典型的な感染シナリオ ― USBメモリ1本から全端末へ

病院でよく聞く感染パターンは、次のような流れです。

1. 職員が自宅から持ち込んだUSBメモリが感染源になる
2. 診療端末・部門端末がほぼ全台、二次感染する。攻撃は比較的ゆっくりだが、対策のない端末には確実に広がる
3. 感染ファイルの駆除とOSの更新を全台で実施。撮影装置のコンソールのように更新できない機器は、感染のたびに再インストール
4. 最終的に、更新できない機器の前にファイアウォールを置いて、院内からの通信を絞る

### 対応の進め方

このとき、ネットワーク側でやることは次の通りです。

- **感染した端末を1台サンプルとして確保**し、通信内容（パケット）を採取して挙動を解析する
- 例えば「ファイル共有やWindowsドメインに使うポート（TCP 139/445）へ、次々にアクセスしている」ことが分かる
- **サーバ向けの通信だけは許可し、端末同士の通信は原則遮断**する設定を入れて、二次感染を止める。ドメイン管理や画像参照など、必要なサーバ通信は通す

:::message
**tips：「端末同士は通信させない」が二次感染を止める一番の近道**
病院の端末は基本的にサーバとしか話す必要がありません。端末～端末間を遮断しておけば、1台が感染しても横に広がりません。無線LANの「クライアント分離」（第4章）も同じ考え方です。平時からこの設定を入れておけば、有事の対応そのものが不要になります。
:::

### 事後に定着させる運用

| 運用 | 内容 | ねらい |
|---|---|---|
| OS更新の2段階適用 | 月例作業とし、一部端末に先行適用して問題がなければ全体適用 | 更新自体の不具合で全端末が止まるリスクの保険 |
| パターンファイルの時間差配信 | 1日2回更新、ただし即時ではなく時間差で配信 | 同上 |
| ファイル共有の制限 | 院内全域で端末のファイル共有機能を制限 | 139/445番ポートの脆弱性は絶えないため |
| USBメモリの使用制限 | 業務端末では原則使用禁止。デジカメなど診療で必要な機器は登録制 | 感染源と情報持ち出しの両方を防ぐ |

:::message
**2026年のアップデート**
サイバーセキュリティ対策チェックリスト（令和8年度版）では、「USBメモリ等の外部媒体の接続ルール」「セキュリティパッチの適用実績の記録」「不要なソフトウェアの停止確認」が明示的に求められています。上の運用は「やっておくと良いこと」から「記録して説明できる状態にしておくこと」に変わりました。
:::

### 脆弱性情報の追い方

JVN（Japan Vulnerability Notes、https://jvn.jp/ ）は、JPCERT/CCとIPAが運営する日本語の脆弱性情報サイトです。使っている製品名で検索する習慣をつけると、ベンダーからの連絡を待たずに動けます。特にネットワーク機器（VPN装置、ファイアウォール、無線コントローラ）の脆弱性は、公表から悪用までの期間が短いので、定期的に確認します。

## 「閉域網だから安全」は成り立たない

「インターネットにつながっていないから大丈夫」という考えは、次の理由で通用しません。

- **USBメモリ経由の侵入**：インターネットから隔離された産業システムに、USBメモリ経由で侵入して設備を停止させたマルウェアの事例が過去にあります。上のUSB感染シナリオも同じです
- **サーバの脆弱性を突く型**：利用者が何も操作しなくても、パッチ未適用のサーバの脆弱性を突いて広がるランサムウェアがあり、医療業界を狙ったものも登場しています
- **保守用の回線**：ベンダーのリモート保守回線やVPN装置は「閉域網の穴」です。国内の病院で電子カルテが長期間停止した事例の多くは、**VPN装置の脆弱性や、保守回線経由の侵入**が入口でした

閉域網ほど「入ってしまった後」の防御（端末間遮断、パッチ、監視、バックアップ）が重要になります。

:::message
**2026年のアップデート：閉域網だけでは済まなくなった**
オンライン資格確認の原則義務化（2023年）、電子処方箋、電子カルテ情報共有サービスなど、医療DXの基盤はいずれも**外部との接続を前提**にしています。「院内は完全閉域」という設計はもう成り立たず、「どこを・どう・誰が通れるか」を設計して管理する（境界を1か所に絞り、ログを取り、認証を強くする）方向に変わっています。安全管理ガイドライン第7.0版でも、**リモート保守経路の限定と接続記録の取得**が求められています。
:::

## 標的型メールの手口

メールで届く攻撃は、受信者の心理を巧妙に突きます。

- 件名や送信者を、業務で来そうなものに偽装する（「請求書」「学会のご案内」など）
- **RLO**（Right-to-Left Override）という「文字を右から左に読ませる制御文字」でファイル名を偽装する。`test[RLO]fdp.exe` が見た目 `testexe.pdf` になる
- アイコンをPDFの画像に差し替える
- 感染のたびに違うファイルを生成し、ウイルス対策ソフトの検知をすり抜ける（ポリモーフィック型）

:::message
**tips：拡張子は必ず表示し、「二重拡張子」と「右から左」に注意**
Windowsの「既知の拡張子を表示しない」設定はオフにします。`.pdf.exe` のような二重拡張子や、RLOで反転したファイル名は、メールゲートウェイ側で自動的に隔離する設定にしておくのが定石です。加えて、実行ファイルの添付は問答無用で止めます。
:::

## なぜ医療機関が狙われるのか

- **貴重な診療情報**：闇市場では、クレジットカード情報よりも医療情報の方が高く取引される
- **脆弱な医療機器**：OSを更新できない機器がネットワークにつながっている
- **止められない業務**：診療を止めるわけにいかないので、身代金を払う圧力が強い
- **人材不足**：専任のセキュリティ担当者がいない施設が多い

つまり、攻撃者から見て「価値が高く、守りが薄く、払いやすい」相手です。国内でも2021年以降、複数の病院でランサムウェアにより電子カルテが数週間～数か月停止する被害が起きています。

:::message
**2026年のアップデート：身代金は払わず、バックアップから戻す**
安全管理ガイドライン第7.0版は、ランサムウェア被害時に身代金の交渉に応じず、**バックアップから復旧する方針**を示しています。そのためには次が前提になります。

- バックアップが**ネットワークから切り離された場所**にもあること（オフライン、または書き換え不可の保存先）。感染したネットワークにつながったままのバックアップは一緒に暗号化される
- **復旧手順が文書化され、実際に戻せることを試したことがある**こと
- **電子カルテ停止時の紙運用手順**を含むBCP（事業継続計画）があること。チェックリスト（令和8年度版）では、サイバー攻撃を想定したBCPが立入検査の現物確認対象です
:::

## 2026年時点で求められていること（整理）

医療機関に対する要求事項は、この数年で「推奨」から「義務」へ移ってきました。ネットワーク担当者に直接関係する部分を整理します。

### 制度の全体像

- **医療法施行規則の改正（2023年4月）**：医療機関にサイバーセキュリティ確保のための措置が義務化された
- **医療情報システムの安全管理に関するガイドライン 第7.0版（2026年6月）**：概説編・経営管理編・企画管理編・システム運用編に加え、保守事業者向けの「保守委託機関編」が新設
- **医療機関におけるサイバーセキュリティ対策チェックリスト（令和8年度版、2026年7月改定）**：立入検査で確認される。医療機関用と薬局用が統合された

### 立入検査で現物確認される4点

1. **サーバ・端末・ネットワーク機器の台帳**（リース機器、PC、複合機を含む。年1回の棚卸し）
2. **インシデント発生時の連絡体制図**（院内、ベンダー、厚生労働省、警察などの連絡先）
3. **サイバー攻撃を想定したBCP**（電子カルテ停止時の紙運用手順など）
4. **運用管理規程**（チェックリストの各項目を、自院でどう実施するかを規程に落とし込む）

### ネットワーク担当者に関係の深い項目

| 項目 | 内容 |
|---|---|
| 二要素認証 | 端末アプリとサーバOSのログイン時に導入。期限は**2027年4月1日**。間に合わない場合は、ネットワーク分離やアクセスログの定期点検などの過渡的措置を文書化 |
| パスワード | 英数字混在。二要素認証を導入するまでは**13桁以上**。「定期変更」の要件は削除され、使い回し禁止が明確化 |
| アクセス制御 | 職種・業務別のアクセス権限、接続元の制限、アクセスログの保存・管理 |
| 管理外機器の遮断 | 台帳にない機器をネットワークにつなげない（802.1X認証など） |
| 無線LAN | ランダムMACアドレスへの対策を明記 |
| ネットワーク分離 | 診療系と情報系（インターネットに触れる系）の分離 |
| リモート保守 | 経路を限定し、接続記録を取得。保守事業者の責任分界を契約で明確化 |
| バックアップ | 診療継続に必要な情報を特定し、バックアップと復旧手順を事業者と協議 |
| パッチ | セキュリティパッチの適用実績を記録 |
| サプライチェーン | 委託先・再委託先のセキュリティ体制を評価 |

:::message
**tips：ネットワーク担当としての優先順位**
全部を一度にはできないので、影響の大きい順に並べるとこうなります。

1. **台帳**を正しくする（第1章）。これがないと他の項目が全部あいまいになる
2. **境界を絞る**：インターネット、リモート保守、VPNの出入口を1か所ずつにして、ログを取る
3. **端末間通信を止める**：VLAN分離とフィルタ、無線のクライアント分離
4. **管理外機器をつなげない**：802.1X認証を監視モードから段階導入（第4章）
5. **バックアップを切り離す**：オフライン保管と復旧試験
6. **二要素認証**：2027年4月の期限から逆算してシステム更改計画に入れる
:::

## スマホ内線・IoT機器が増えると、無線は「止まってはいけないインフラ」になる

PHSの製造・保守終了に伴い、スマートフォンを院内内線とナースコール端末にする病院が増えています。PHSと比べて、患者名や呼出種別が画面に出る、着信が速い、基地局あたりの接続台数制限がない、といった利点があります。

一方で、スマホ内線を無線LANに載せると、無線LANが止まった瞬間に**電話もナースコールも止まります**。第3章の「コントローラ障害で全断」のような事故が、通信障害ではなく「連絡手段の喪失」になります。

さらに、輸液ポンプ、生体モニタ、X線の検出器、服薬管理の箱など、無線でつながる医療機器やIoT機器が増え続けています。これらは次の特徴があります。

- OSを更新できない、あるいは更新に承認が必要
- 古い無線規格や暗号方式しか対応しないことがある
- 台数が多く、台帳から漏れやすい

:::message
**tips：IoT・医療機器は「専用SSID＋専用VLAN＋通信先の限定」**
医療機器の脆弱性を直せないなら、ネットワーク側で囲います。専用のSSIDとVLANに収容し、その機器が話す必要のあるサーバ以外への通信をフィルタで止めます。「古い機器に全体を合わせる」のではなく「古い機器を隔離する」のが原則です。
:::

## 全体のまとめ ― 病院ネットワーク運用の鉄則

この本で繰り返し出てきた考え方を、6つにまとめます。

1. **見えないものを見える化する**：有線はSNMP・ログ・統合監視、無線はサイトサーベイ・電波の可視化・`netsh wlan`。見えていないものは守れないし、直せない
2. **端末同士を話させない**：有線は端末間通信の遮断、無線はクライアント分離。二次感染も盗聴も、これで大半を防げる
3. **業務系と患者系は"周波数帯ごと"分ける**：VLANや物理分離だけでは電波の干渉は防げない
4. **導入時に障害試験を必ずやる**：冗長化・フェイルオーバー・RADIUS停止時の挙動は、本番で初めて分かるのでは遅い。ベンダーに試験と報告書を求める
5. **ログは最低1か月、外部に保管**：「落ち際の1通のトラップ」が原因究明の糸口。監視のためだけでなく、説明責任のためにも
6. **ネットワーク用語を知ることが、業者の見積と障害切り分けの両方を速くする**：用語が分かれば、任せきりにしなくて済む

そして2026年の追加として、**「推奨」だったことの多くが「義務」になった**ことを押さえておきます。台帳、BCP、二要素認証、リモート保守の記録は、立入検査で確認される項目です。技術的にできているだけでなく、規程と記録で「説明できる」状態にしておくことが、いまのネットワーク担当者に求められています。
