## この章の要点（忙しい人向け）

- トラブルは**下の階層から**切り分ける（ケーブル → リンク → IP → ポート → アプリ）
- スイッチはMACアドレス、ルータはIPアドレスで宛先を決める。VLANは「分ける」技術で、VLAN間の通信にはL3機器が必要
- 冗長化するならループ対策（STP・ループ検知）をセットで入れる
- AP更新時は**PoEの規格と給電総量**を確認する。混雑対策は回線増強かQoSで、QoSは経路上の全機器で一貫させる

## なぜ基礎を知る必要があるのか

病院では、電子カルテの導入業者がネットワークも一緒に構築することが多く、情報システム部門にネットワークの専門家がいないケースが珍しくありません。「アプリケーションの専門家」と「ネットワークの専門家」は別物なので、次のようなことが起きます。

- 「電子カルテの反応が遅い」→ 業者はアプリのバグを熱心に調査 → 数日後「アプリは問題なし、ネットワークかも」→ 対応が後手に
- 「専用のネットワークを作ってほしい」→「VLANの追加と経路の変更が必要です」→「作業費は○○万円です」→ 妥当かどうか判断できない

この章の目的は、この2つを減らすことです。基礎用語が分かると、障害の切り分けも見積の妥当性判断も自分でできるようになります。

## OSI参照モデル ― 通信を7つの階層で考える

通信に必要な機能を7つの階層に分けたのが**OSI参照モデル**です。分けることで「ある階層の変更が上下に影響しない」「アプリを作る人は下の仕組みを知らなくても通信できる」という利点があります。

実務で覚えておくべきは、次の対応表です。

| 階層 | 名前 | 役割（ざっくり） | 使う「住所」 | 代表的な機器 |
|---|---|---|---|---|
| 7 | アプリケーション | HTTP、DNS、メールなどアプリの取り決め | – | ロードバランサ、IPS |
| 4 | トランスポート | TCP / UDP。データを確実に届ける仕組み | ポート番号 | ファイアウォール |
| 3 | ネットワーク | 異なるLAN同士をつなぐ | IPアドレス | ルータ、L3スイッチ |
| 2 | データリンク | 直接つながった隣同士の通信 | MACアドレス | L2スイッチ、無線AP |
| 1 | 物理 | ケーブル、電気信号、光信号 | – | ハブ、ケーブル |

（5・6層は実務ではあまり意識しないので省略しています）

:::message
**tips：トラブルの切り分けは「下の階層から」**
OSIを覚える一番の実益はこれです。トラブル時に「ケーブルは挿さっているか（L1）→ リンクランプは点いているか（L1/L2）→ IPアドレスは正しいか、pingは通るか（L3）→ ポートは開いているか（L4）→ アプリは動いているか（L7）」と下から順に確認できます。上から疑うと、アプリの調査に何日も費やしたあとで「ケーブルが半抜けだった」ということが起きます。
:::

### データは「封筒を何重にも重ねて」送られる

送りたい情報には、階層ごとに宛名（ヘッダ）が付け足されて回線に流れます。

```
[Ethernetヘッダ(MAC)] [IPヘッダ(IP)] [TCP/UDPヘッダ(ポート)] [アプリのヘッダ] [情報]
```

受け側は逆順に剥がします。パケットキャプチャ（Wiresharkなど）を見ると、この構造がそのまま表示されます。「どの階層で問題が起きているか」を見るには、この重なりを頭に置いておくと読みやすくなります。

## レイヤ1（物理層）― ケーブルとPoE

### 銅線と光ファイバ

| | 銅線（UTP）ケーブル | 光ファイバケーブル |
|---|---|---|
| 距離 | 最大100m | 数kmでも可 |
| 取り回し | 折り曲げに強く容易 | 折れやすく難しい |
| ノイズ | 外部の電気ノイズの影響を受ける | 受けにくい |
| 価格 | 比較的安価 | 比較的高価 |

病院では、建物間や階をまたぐ幹線は光ファイバ、各部屋への支線は銅線、という組み合わせが一般的です。医療機器や大型モーターの近くを銅線が通ると、ノイズで通信が不安定になることがあります。

### PoE ― LANケーブルで電気も送る

**PoE**（Power over Ethernet）はLANケーブルで電力も送る技術で、無線AP・IP電話・ネットワークカメラを電源工事なしで設置できます。

| 規格 | 最大供給電力 | 主な用途 |
|---|---|---|
| IEEE 802.3af（PoE） | 15.4W | IP電話、古い無線AP |
| IEEE 802.3at（PoE+） | 30W | 一般的な無線AP、カメラ |
| IEEE 802.3bt（PoE++） | 60W / 90W | Wi-Fi 6E/7の高性能AP、多機能端末 |

:::message
**tips：AP更新時は「スイッチのPoE規格」と「給電総量」を確認する**
「APを新しくしたら起動しない・性能が落ちる」はよくある落とし穴です。Wi-Fi 6E/7のAPは802.3at以上（製品によっては802.3bt）を必要とすることが多く、802.3afのスイッチでは動きません。さらに、スイッチには「全ポート合計で何Wまで供給できるか」という上限（PoEバジェット）があり、24ポート全部にAPをつなぐと足りないことがあります。見積の段階で、AP1台あたりの必要電力 × 台数 がスイッチの給電総量に収まるか確認します。
:::

## レイヤ2（データリンク層）― スイッチ・MACアドレス・VLAN

### スイッチの動き

スイッチは**MACアドレステーブル**（どのポートの先にどのMACアドレスの機器がいるか）を持ち、宛先のポートだけにデータを送ります。宛先がテーブルにないときは、受信したポート以外の全ポートに送ります（**フラッディング**）。

MACアドレスは「全世界で一意」に割り当てられていますが、「ソフトウェアで書き換え可能」でもあります。この2つは同時に覚えておいてください。MACアドレスで端末を制限する仕組み（第4章のMAC認証）は便利ですが、なりすましは技術的に可能なので「MACだけで強固」とは考えないのが大事です。

### 冗長構成とブロードキャストストーム

スイッチ同士を2本以上でつなぐと迂回経路ができて安心です。しかし、全員宛の通信（ブロードキャスト）はスイッチが「どのポートに送るべきか」を学習しないため、輪の中を延々と回り続けます。これが**ブロードキャストストーム**で、第1章の「抜けたケーブルを挿す事故」と同じ現象です。

これを防ぐのが**スパニングツリー**（STP）です。スイッチ同士が情報を交換して配線の全体像を把握し、ループになるポートを1つ自動で遮断します。手順は「ルートブリッジ（中心のスイッチ）を決める → 各スイッチでルートに一番近いポート（ルートポート）を決める → 区間ごとに代表ポートを決める → 残りを遮断」の順で、ルートブリッジは「優先度の数字が一番小さいスイッチ」が選ばれます。

:::message
**tips：ルートブリッジは自分で決める**
優先度を設定しないと、全スイッチが同じ値になり、MACアドレスが一番小さい（＝たいてい一番古い）スイッチが勝手にルートになります。基幹スイッチの優先度を明示的に小さくして、意図した構成にしておきます。
:::

### VLAN ― 1台のスイッチを論理的に分ける

**VLAN**は「1台のスイッチを論理的に複数のスイッチに分ける」技術です。定義としては「VLAN ＝ ブロードキャストの流れる範囲」と覚えると、ほかの概念とつながります。

部署ごとにスイッチを買わなくても、電子カルテ系（VLAN10）と事務系（VLAN20）と患者向け（VLAN30）を同じスイッチで分離できます。1階と2階に部署がまたがっていても、VLANなら対応できます。

- **アクセスポート**：端末をつなぐポート。1つのVLANに所属し、VLANのタグを認識しない
- **トランクポート**：スイッチ同士やスイッチとAPをつなぐポート。データに「VLAN番号のタグ」を付けて、複数VLANを1本のケーブルで運ぶ

:::message
**tips：VLANを分けても「ルータかL3スイッチ」がないとVLAN間は通信できない**
VLANは分離する技術なので、VLAN10とVLAN20を通信させるにはレイヤ3の機器で中継します。「分けたら通らなくなった」は、この中継設定（と通信フィルタ）の抜けが原因のことが多いです。逆に言えば、「電子カルテ系と患者Wi-Fiを絶対に通信させない」なら、L3で中継しない（またはフィルタで止める）だけで実現できます。
:::

## レイヤ3（ネットワーク層）― IPアドレスとルーティング

### IPアドレスとサブネットマスク

IPアドレスは32ビットの数字で、**サブネットマスク**によって「ネットワーク部」と「ホスト部」に分かれます。

例：`192.168.1.1 / 255.255.255.0`（`/24` とも書く）
→ `192.168.1` までがネットワーク部（どのネットワークか）、最後の `1` がホスト部（そのネットワーク内のどの機器か）

同じネットワーク部を持つ機器同士は直接通信でき、違うネットワーク部の機器とはルータを経由します。

### デフォルトゲートウェイ

**デフォルトゲートウェイ**は「自分と違うネットワーク宛の通信を任せるルータ」です。端末は宛先が同じネットワークなら相手のMACアドレス宛に直接送り、違うネットワークならデフォルトゲートウェイのMACアドレス宛に送ります。

端末の設定で必要なのは、IPアドレス・サブネットマスク・デフォルトゲートウェイ・DNSサーバの4つです。このどれかが間違っていると「同じ部屋の機器とは話せるのにサーバに届かない」といった中途半端な症状になります。

### ルーティングテーブル

ルータは「宛先ネットワーク／マスク／出口ポート／次の転送先（ネクストホップ）」の表を持っています。

| 宛先ネットワーク | マスク | 出口 | ネクストホップ |
|---|---|---|---|
| 192.168.1.0 | /24 | ポート1 | 直接接続 |
| 192.168.2.0 | /24 | ポート2 | 直接接続 |
| 0.0.0.0 | /0 | ポート3 | 上位ルータ |

- 宛先がどの行にもなければ、ルータはそのデータを**破棄**します
- `0.0.0.0/0` の行（**デフォルトルート**）を入れておくと、表にない宛先はすべてそこへ送られます。インターネット向けの通信はこれで流れます

経路の設定方法は2種類です。

- **スタティックルート**：管理者が手で経路を書く。小規模向け、確実
- **ダイナミックルート**：ルータ同士が自動で経路を交換する（OSPF、BGPなど）。大規模向け

:::message
**tips：「行き」だけでなく「戻り」の経路も必要**
pingが片道だけ届いて応答が返ってこない、というトラブルの多くは、相手側のルータに「戻り道」の設定がないことが原因です。新しいネットワークを追加したときは、行きと戻りの両方の経路を確認します。
:::

### プライベートIPアドレス

院内だけで使えるIPアドレスの範囲は3つあります。

| 範囲 | 書き方 |
|---|---|
| 10.0.0.0 ～ 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 ～ 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 ～ 192.168.255.255 | 192.168.0.0/16 |

昔は「クラスA/B/C」という分類がありましたが、現在はサブネットマスクで自由に分ける方式（CIDR）が標準です。ただし、この3つの範囲を覚えるうえではクラスの知識が今でも役に立ちます。

:::message
**tips：他施設・他システムとつなぐ前提でアドレスを決める**
地域医療連携、オンライン資格確認、遠隔画像診断などで、他のネットワークと接続する機会が増えています。相手と同じアドレス範囲を使っていると、接続時にアドレス変換（NAT）が必要になり、設定が複雑になります。新しく設計するときは、`192.168.0.0/24` や `192.168.1.0/24` のような「誰でも使っていそうな範囲」を避けると、後で楽になります。
:::

## 帯域とQoS（優先制御）

1Mbpsの回線に5Mbpsの動画を流せば当然詰まります。対策は「回線を増強する」か「大事な通信を優先させる」の2つで、後者が**QoS**（Quality of Service）です。

何もしなければ全通信が平等に扱われ、混雑時は平等に捨てられます（ベストエフォート）。QoSは次の4つの技術の組み合わせです。

1. **識別**：どの通信が大事か、データに印を付ける
2. **輻輳回避**：混む前に、重要でない通信から捨てる
3. **帯域制御**：特定の通信に固定の帯域を割り当てる
4. **優先制御**：大事な通信を先に送る

病院では「ナースコール・音声通話・生体モニタ」を高優先、「患者Wi-Fi・動画配信」を低優先にするのが典型です。

:::message
**tips：QoSは「印を付ける機器」と「印を見る機器」の両方で設定する**
端末の近くのスイッチで印を付けても、途中のスイッチがその印を無視すれば効きません。経路上の全機器で一貫した設定が必要なので、ベンダーが分かれている場合は「どの印（DSCP値）を使うか」を最初に合わせておきます。
:::

## この章のまとめ

- トラブルは**下の階層から**切り分ける（ケーブル → リンク → IP → ポート → アプリ）
- スイッチは**MACアドレス**で、ルータは**IPアドレス**で宛先を決める
- **VLAN**は分離する技術。VLAN間の通信にはL3機器が必要
- 冗長化するなら**ループ対策**（STP、ループ検知）をセットで
- AP更新時は**PoEの規格と給電総量**を確認する
- 混雑対策は**回線増強かQoS**。QoSは経路上の全機器で一貫させる
