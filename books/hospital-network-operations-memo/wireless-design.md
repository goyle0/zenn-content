## この章の要点（忙しい人向け）

- 無線トラブルは電波の6つの性質（減衰・反射・回折・透過・干渉…）で説明できる。同時に話せるのは1台で、遅い端末が全員を遅くする
- 2.4GHzは実質3チャネル、5GHzは19チャネルで**DFS**に注意。6GHzはDFSなし・WPA3必須
- 設計は**サイトサーベイ**で実測し、いちばん弱い端末に合わせる。SSIDは帯域で分け、増やしすぎない
- 業務系と患者系は**周波数帯で分ける**。AP更新はPoEとケーブル速度とセットで考える

## 電波の6つの性質 ― 無線トラブルの原因はほぼこの中にある

電波は「波」の一種で、海の波・音・光と同じ性質を持ちます。無線LANのトラブルは、突き詰めるとこの6つのどれかで説明できます。

| 性質 | 何が起きるか | 身近な例 |
|---|---|---|
| 振動 | 振幅が「強さ」、波長が「周波数」を決める | 寄せては返す波 |
| 減衰 | 遠くへ行くほど弱くなる | 波紋はいつか消える |
| 反射 | 物に当たると跳ね返る | やまびこ |
| 回折 | 曲がって障害物を越える。**周波数が低いほど曲がりやすい** | 山の向こうでもAMラジオは聴こえるが、FMは聴こえない |
| 透過・吸収 | 突き抜けたり、吸収されたりする | 隣の部屋の音が聞こえる／防音室 |
| 干渉 | 波同士がぶつかると強め合ったり弱め合ったりする | ノイズキャンセリングヘッドホン |

:::message
**tips：「2.4GHzは遠くまで届き、5GHz/6GHzは速いが届きにくい」は回折の性質から**
周波数が低い2.4GHzは曲がって回り込むので、壁の向こうにも届きやすい。5GHzや6GHzは直進性が強く、壁や扉で大きく減衰します。「5GHzに切り替えたら遅くなった」というトラブルの原因はほぼこれで、5GHz中心の設計ではAPを多めに置くのが基本です。
:::

## 無線LANの基本ルール

- 隣り合うAPは違うチャネル（電波）にしないと干渉する
- 使うエリアに満遍なく電波が届かないと通信できない
- 電波が強いほど速い、規格が新しいほど速い
- **同時に通信できる端末は1台だけ**（同じチャネルの端末全員で空間を共有し、順番に話す）

最後の1つは特に重要です。古い規格の遅い端末が1台つながっていると、その端末が長い時間を使うので、他の端末全員が待たされます。

## 規格と周波数帯

### 規格の一覧（2026年時点）

| 規格 | 通称 | 周波数帯 | 最大速度（理論値） | 主な特徴 |
|---|---|---|---|---|
| 802.11b | – | 2.4GHz | 11Mbps | もう使わない |
| 802.11g | – | 2.4GHz | 54Mbps | 古い医療機器に残っていることがある |
| 802.11a | – | 5GHz | 54Mbps | 同上 |
| 802.11n | Wi-Fi 4 | 2.4 / 5GHz | 600Mbps | MIMO、40MHz幅 |
| 802.11ac | Wi-Fi 5 | 5GHz | 6.9Gbps | 80/160MHz幅、MU-MIMO |
| 802.11ax | Wi-Fi 6 | 2.4 / 5GHz | 9.6Gbps | OFDMA（多数端末に強い）、TWT（省電力） |
| 802.11ax | Wi-Fi 6E | 6GHz | 9.6Gbps | 6GHz帯を追加。日本では2022年9月に解禁 |
| 802.11be | Wi-Fi 7 | 2.4 / 5 / 6GHz | 46Gbps | 320MHz幅、4096-QAM、MLO（複数帯域の同時利用）。日本では2023年12月に解禁 |

:::message
**2026年のアップデート**
- Wi-Fi 6EとWi-Fi 7は日本でも解禁済みで、対応APと端末が普通に買えます。6GHz帯は日本では5925～6425MHzの範囲で、屋内利用が基本です
- **6GHz帯はWPA3が必須**です（WPA2やWEPは使えません）。古い端末は6GHzにつなげないので、Wi-Fi 7のAPを入れても、2.4/5GHzのSSIDは引き続き必要になります
- Wi-Fi 6の**OFDMA**は「1回の送信を細かく分けて多数の端末に同時に配る」技術で、病棟のように端末が密集する環境で効きます。**TWT**は端末が「次に起きる時刻」をAPと約束して眠る機能で、バッテリー駆動の機器に向いています
- Wi-Fi 7の**MLO**は、2.4/5/6GHzを同時に使って1本の接続に見せる機能で、帯域の切り替えによる通信断が減ります。ただし端末側の対応が必要です
:::

### 2.4GHz帯 ― 使えるチャネルは実質3つ

2.4GHz帯はチャネル間隔が5MHzなのに、1チャネルの幅が20～22MHzあります。隣のチャネルと重なるため、干渉せずに同時に使えるのは**1ch / 6ch / 11ch の3つだけ**です。

日本では13chまで使えるため、20MHz幅なら「1 / 5 / 9 / 13」の4チャネル取りに行く設計も可能です。ただし古い11b端末（22MHz幅）が混ざると重なるため、業務系では1/6/11が無難です。

2.4GHz帯は電子レンジ、Bluetooth、コードレス電話、一部の医療機器（テレメータの一部など）とも干渉するため、新規設計では「**2.4GHzは古い機器の救済用、主力は5GHz以上**」と割り切ります。

### 5GHz帯 ― 19チャネルとDFS

5GHz帯はチャネル間隔と幅がどちらも20MHzなので、隣接チャネルは干渉しません。同じチャネルが隣り合うと「順番待ち（競合）」になって遅くなります。

| 帯域 | チャネル | 屋外利用 | DFS |
|---|---|---|---|
| W52（5.2GHz帯） | 36, 40, 44, 48 | 原則×（屋内のみ） | 不要 |
| W53（5.3GHz帯） | 52, 56, 60, 64 | ×（屋内のみ） | **必要** |
| W56（5.6GHz帯） | 100 ～ 140（機器によっては144も） | ○ | **必要** |

**DFS**（Dynamic Frequency Selection）は、気象レーダーなどの電波を検出したら、そのチャネルを即時に変更して一定時間使わない仕組みです。法律で義務付けられています。問題は、チャネル切り替えに対応していない端末が、このときに切断されることです。

:::message
**tips：安定第一ならW52の4チャネルだけで設計する**
DFS不要で、端末の対応も広い帯域です。ただし4チャネルしかないので、AP密度が高い病棟では足りず、W53/W56も使う設計になります。その場合は「DFS対応端末かどうか」「チャネル切替に追従できるか」を、医療機器や古い端末について導入前に確認します。「端末が不定期に切れる」という申告があったら、まずDFSを疑います。
:::

:::message
**2026年の補足：6GHz帯はDFS不要**
6GHz帯にはレーダーがいないのでDFSがありません。DFSに悩まされてきた環境にとっては、Wi-Fi 6E/7への更新は「速くなる」以上に「切れなくなる」メリットがあります。ただし端末側が6GHz対応である必要があります。
:::

## SSID・BSSID・ローミング

- **SSID（ESSID）**：一般に「SSID」と呼ばれるネットワーク名
- **BSSID**：AP1台ごと（正確には無線1つごと）の固有ID。APのMACアドレスから作られる
- **MACアドレス**：APの有線側の固有アドレス

端末は「同じSSID」のAPならどれにでもつなげます。別のAPへ移る（**ローミング**）ときは、数秒の通信断が起きます。

:::message
**tips：`netsh wlan show interfaces` で「今どのAPにつながっているか」が分かる**
Windowsのコマンドプロンプトで実行すると、SSID・BSSID・チャネル・受信/送信速度・シグナル（%）・認証方式・無線の種類（802.11ax など）が出ます。「近くのAPではなく遠くのAPにつながっている」「頻繁にBSSIDが切り替わる」がこの1コマンドで見えるので、無線トラブルの第一手にしてください。Windows 11でもそのまま使えます。
:::

## 自律型APと集中管理型AP

| | 自律型AP | 集中管理型AP（無線LANコントローラ / クラウド管理） |
|---|---|---|
| 設定変更 | 1台ずつ | コントローラから複数台に一括 |
| メリット | 低コスト | 電波強度・チャネル・接続端末を全体で把握。チャネルや出力の自動調整 |
| デメリット | 台数が多いと管理が煩雑 | 高コスト。製品によっては通信がコントローラを経由するため、**コントローラ故障で全無線が停止 → 冗長化が必須** |

病院規模なら集中管理型が前提です。コントローラを冗長化したうえで、**導入時に「コントローラを片方止めても通信が続くか」の障害試験を必ず実施**します。「フェイルオーバーの設定ミスで全断」は実際によく起きる事故です。

:::message
**2026年の補足：クラウド管理型**
コントローラ機器を院内に置かず、クラウドから管理するタイプのAPが増えています。通信自体はAPから直接流れるので、管理サーバとの接続が切れても既存の通信は続く製品が多いですが、「管理接続が切れたときに何ができなくなるか」は製品ごとに違うので確認が必要です。
:::

## 構築時のポイント①：電波設計

自宅と業務用の一番の違いは「カバーする広さ ＝ APの台数」です。複数台のAPで快適な環境を作るには、限られたチャネルを最適な位置に配置する「チャネルと電波出力の設計」が必要で、怠ると次の4つのトラブルが起きます。

### よくある4つのトラブル

1. **干渉・競合**：2.4GHzで周波数が重なると干渉。同じチャネルが隣接すると順番待ちで遅くなる
2. **カバレッジホール**：そもそも電波が届かない場所
3. **スティッキー問題**：移動しても最初につないだ遠いAPを掴んだままで、電波が非常に弱くなるまで切り替わらない
4. **ピンポン問題**：同じくらいの強さのAPが複数あり、電波の揺らぎで接続と切断を繰り返す

### 電波強度（RSSI）の目安

電波の強さは **dBm** というマイナスの数字で表し、0に近いほど強い電波です。

| 値 | 状態 |
|---|---|
| -50dBm前後 | 非常に強い |
| -65dBm | タブレットが安定して使える最低ライン |
| -70dBm | まずまず。業務用途の設計目標 |
| -75dBm | ノートPCが安定して使える最低ライン |
| -80dBm以下 | 不安定。隣のビルや敷地外からの外来波はこのあたりが多い |

「タブレットの方がノートPCより厳しい」のは、タブレットやスマホのアンテナが小さく、感度が低いためです。**設計はいちばん弱い端末に合わせます**。

### サイトサーベイ ― 図面だけで設計しない

**サイトサーベイ**とは、実際にAPを仮置きし、専用ツールで電波を可視化して、チャネルと出力を設計することです。図面だけの設計（予測サーベイ）で済ませると、「図面上は等間隔に置いたのに届かない場所がある」ことになります。

電波の減衰は材質によって大きく変わります：ガラス ＜ 合板 ＜ 木材 ＜ コンクリート ＜ 鉄筋コンクリート。さらに人・空気中の水分・ホコリも影響します。「廊下に置いたAPで室内をカバーするつもりが届かない」は典型的な失敗です。病院は鉛入りの壁（放射線区画）や金属製の扉が多く、図面と実測のズレが特に大きい環境です。

:::message
**tips：APの出力は「強ければ良い」わけではない**
出力を上げると遠くまで届く反面、隣のAPと重なる範囲が増えて干渉・スティッキー・ピンポンが悪化します。また、端末側の送信出力はAPより弱いので、APだけ強くしても「APの声は届くが端末の声が返らない」片通話になります。カバレッジホールの対策は、出力を上げるよりAPを足す方が筋が良いことが多いです。
:::

## 構築時のポイント②：SSID設計

同じSSIDのAPが複数あると、電波が届く限りどのAPにもつながり、意図しないローミングが起きます。2.4GHzと5GHzの両対応APで同じSSIDにすると、**2.4GHzと5GHzの間でもローミングし、電波は強いのに頻繁に切断・再接続**することがあります。

対策は次の通りです。

- 部門ごと・フロアごとにSSIDを分ける
- **2.4GHzと5GHzで別のSSIDにする**（例：`ward-2f` と `ward-2f-5g`）
- 端末側で5GHzを優先する設定にする
- 端末側の「ローミングの積極性」を調整する

最近のAPには、端末を空いている帯域へ誘導する**バンドステアリング**があり、同じSSIDでも5GHzへ寄せられるようになってきました。ただし端末側の対応が必要で、医療機器や古い端末が混在する病院では、SSIDを帯域で分けた方がトラブルは少ないです。

:::message
**tips：SSIDは増やしすぎない**
SSIDを1つ増やすごとに、APは「ここにこのSSIDがあります」という信号（ビーコン）を定期的に出します。SSIDが10個あると、電波の一部が常にビーコンで埋まります。用途別に3～4個（業務系、患者向け、IoT・医療機器用など）に絞るのが目安です。
:::

## 病院特有の「無線を不安定にする要因」

### 外的要因

- 患者・来訪者がWi-Fiを使いたくてモバイルルータやテザリングを持ち込む → 電波干渉
- 誰がどこで使っているか分からず、見つけても使わせないようにするのは難しい
- 院内のSSIDを装った偽のAPが立てられる可能性もある

### 内的要因

- 診療科ごと・機器メーカーごとにバラバラにAPを設置する文化 → 同じチャネルで干渉、無線資源の無駄遣い、コスト増
- 無線内蔵の医療機器（X線の平面検出器、輸液ポンプ、生体モニタなど）が増え続けている

### 解決の方向

- **統合的なポリシー**を作り、APの設置を情報システム部門に一元化する
- 院内の干渉状況を**定期的に監視**する（不正AP、電子レンジなどの非Wi-Fi干渉源の位置特定）
- 患者向けWi-Fiを**禁止するのではなく、公式に提供する**。禁止しても持ち込み機器が増えて干渉が悪化するだけで、管理された公式Wi-Fiを提供する方が、干渉もセキュリティも制御下に置ける

参考になる公的資料として、電波環境協議会の「医療機関において安心・安全に電波を利用するための手引き」があります。医療機器への電波の影響、無線LANの設計、持ち込み機器の扱いなどが整理されています。

## 業務系と患者系をどう分けるか

患者向けWi-Fiを提供するときの構成は2通りです。

| | 物理分離（患者用を別ネットワークとして新設） | 論理分離（既存ネットワークにVLANで同居） |
|---|---|---|
| メリット | 故障・トラブル時に他システムに影響しない | 既存機器を流用、新規配線不要、追加APの電波問題を考えなくて済む、一元管理 |
| デメリット | 機器・保守・配線の初期費用が高い。業務系APと電波が混在する | 障害時に他システムへ影響。APを共同利用するので性能が出にくい場合がある |

:::message
**tips：物理分離しても「電波」は分離できない**
物理的に別ネットワークにしても、同じ周波数なら電波の届く範囲で干渉します。だから設計では**周波数帯そのものを分けます**。たとえば「電子カルテ系は5GHz（W52）、患者系は2.4GHz または 5GHz（W53）」のように分ければ、「患者Wi-Fiを入れたら電子カルテが遅くなるのでは」という心配はほぼ解消できます。Wi-Fi 6E/7が使えるなら「業務系を6GHz、患者系を5GHz」という分け方も選べます。
:::

## 無線高速化の技術 ― 用語の意味だけ押さえる

| 技術 | ひとことで | 注意 |
|---|---|---|
| 変調の多値化（QAM） | 1回の信号に載せる情報量を増やす。Wi-Fi 4の64QAM → Wi-Fi 6の1024QAM → Wi-Fi 7の4096QAM | 電波が強くないと高い多値は使えない |
| MIMO | 複数アンテナで同時送受信 | AP・端末とも複数アンテナが必要 |
| MU-MIMO | 複数端末に同時送信 | 端末側も対応が必要 |
| OFDMA（Wi-Fi 6以降） | 1回の送信を細かく分けて多数の端末に配る | 端末が密集する環境で効く |
| チャネルボンディング | 隣のチャネルを束ねて20MHz → 40/80/160/320MHz。速度は倍々 | 使えるチャネル数が減り、干渉が増える |
| エアタイム・フェアネス | 時間で均等に割り振り、遅い端末の独占を防ぐ | 「遅い端末が全員の足を引っ張る」対策 |
| バンドステアリング | 空いている周波数帯（主に5GHz以上）へ誘導 | 端末側も対応が必要 |
| MLO（Wi-Fi 7） | 複数の帯域を同時に使って1本の接続にする | 端末側も対応が必要 |

:::message
**tips：広いチャネル幅は「速いが干渉しやすい」**
80MHzにするとW52の4チャネルが「1チャネル」に化けます。AP密度の高い病棟で80MHzを使うと、隣のAPと必ず同じチャネルになって競合します。病院では5GHzは20MHzか40MHzで運用してチャネル数を確保し、広い幅を使うなら6GHz帯で、というのが現実的です。
:::

## 意外な盲点：APの「有線側」がボトルネックになる

Cat5eケーブルの上限は1Gbpsです。Wi-Fi 6以降のAPは無線側で数Gbps出るため、既存のLANケーブルが渋滞の原因になります。

| ケーブル | 速度 | 距離 |
|---|---|---|
| Cat5e | 1Gbps（マルチギガ対応スイッチなら2.5Gbps） | 100m |
| Cat6 | 1Gbps、10Gbpsは55mまで（マルチギガなら5Gbps） | 100m |
| Cat6A | 10Gbps | 100m |
| Cat7 | 40Gbps | 30m（コネクタもRJ45ではない） |

対策は**マルチギガビット・イーサネット**（mGig / NBASE-T、IEEE 802.3bz）対応スイッチへの入れ替えです。配線工事なしに、Cat5eで2.5Gbps、Cat6で5Gbpsが出せます。

:::message
**tips：AP更新の見積では「PoE規格」と「マルチギガ対応」の2点を確認する**
第2章のPoE（電力）とこの章のケーブル速度は、どちらも「APだけ新しくしても性能が出ない」原因です。AP更新とスイッチ更新はセットで考えます。逆に、既存スイッチが1Gbps・802.3atのままなら、Wi-Fi 7のAPを入れても性能を出し切れないので、「Wi-Fi 6のAPで十分」という判断もあり得ます。
:::

## この章のまとめ

- 無線トラブルは電波の**6つの性質**（減衰・反射・回折・透過・干渉…）で説明できる
- **同時に話せるのは1台**。遅い端末が全員を遅くする
- 2.4GHzは実質3チャネル、5GHzは19チャネル。**DFS**に注意。6GHzはDFSなし・WPA3必須
- 設計は**サイトサーベイ**で実測し、いちばん弱い端末に合わせる
